> Minimum fix now: wire them, or mark disabled with a "Próximamente" tooltip so they don't read as broken.

**Driver: proof-of-delivery is still faked** (the receiver-name gate is the only part fixed):
- `DriverApp.tsx:299,303` — "Navegar" / "Llamar" are no-ops (no `tel:` / maps link).
- `DriverApp.tsx:387-414` — photo is a toggle showing hardcoded `FOTO_CARGA_01.jpg`; no camera/file input, no upload.
- `DriverApp.tsx:420-438` — signature is a toggle showing hardcoded "Andrés R."; no signature pad.
- `DriverApp.tsx:488` — done-screen "Hora" is the literal string "11:32 a. m.", not the real time.
- Note: `lib/storage.ts` already exposes `uploadCumplido()` / `uploadFirma()` with RLS, but `DriverApp` never imports them — the wiring is the gap.

### P1 — Robustness & auth (verified still open)
- **Logout has no try/catch** — `DashboardShell.tsx:261`, `DriverApp.tsx:132`, `useAuth.ts:95`. Failed `signOut()` redirects to login while the session may persist.
- **No password reset** — `login/page.tsx:121` "¿Olvidaste tu contraseña?" is `href="#"`.
- **No login rate-limit feedback**; **no explicit session-expiry handling** in `useAuth` `onAuthStateChange`.
- **Redirect hardening (minor):** `safeRedirect()` blocks the known payloads; consider `new URL()`-based validation over `startsWith` string checks for defense-in-depth. (No concrete bypass found — hardening, not an active hole.)

### P1 — Missing infrastructure (whole app)
- **No `error.tsx`** → unhandled errors show the raw Next.js page.
- **No `loading.tsx`** → no skeletons once real fetches land.
- **No `not-found.tsx`** → off-brand 404.
- **No login form validation** (only `required`; `Input` supports `aria-invalid`, unused).
- **No empty states** — zero-data days render blank tables.
- **PWA is cosmetic** — manifest + icons exist, but **no service worker** → no offline (most needed for the driver in low-signal areas).

### P1 — Missing functionality by role (the Phase-1 build)
**Driver:** GPS capture on arrival/departure (schema has `latitude`/`longitude`, never written); real photo→Storage + signature; **novedades** issue-reporting (no UI at all); "today's own deliveries" filter (loads a mock array, `useAuth()` unused for scoping); realtime status sync.
**Coordinator:** real map (`LiveMap.tsx` is a static SVG placeholder); **alert escalation** (`AlertsCard` rows are read-only — the "truck stopped >60 min → escalate" loop isn't met); route/driver/client **detail views** (rows not clickable); **malla** weekly planner (absent); Supabase Realtime; live date/counts (`dashboard/page.tsx:24` is the static "Lunes 15 de enero…").
**Admin:** client CRUD; invoice creation + status transitions; report generation/export (buttons decorative); **PeriodToggle not wired** (topbar state no page reads); **AR aging / DSO** (in spec, absent); **driver-management page** (`/admin/conductores` doesn't exist).

**Systemic:** **0 of 9** dashboard/admin/driver pages issue a `supabase.from()` query or Realtime subscription — all data is from `lib/mock/*`. This is the root dependency for nearly every item above.

### P2 — Accessibility (35 serious/critical, all `color-contrast`)
Worst: landing `/` dark 13 (desktop)/12 (mobile); `/admin` dark 11 / light 9; several `/dashboard/*` 5–7. Fix muted-foreground tokens to meet 4.5:1 (3:1 large text), especially dark-mode landing captions and admin secondary text.

### Minor / polish
- Wide tables (clientes, facturación) **clip on mobile** — right columns cut off; add horizontal scroll affordance or a card layout at `sm`.
- `manifest.ts` `theme_color:#0A0A0A` shows a dark status bar even in light mode — consider dynamic or brand green.
